Installing skills with npx skills

What is npx skills?

vercel-labs/skills is an open, GitHub-backed package manager for agent skills — reusable instruction sets (a SKILL.md plus any supporting files) that extend AI coding agents. Think “npm, but the registry is GitHub and the packages are skills.” It supports Claude Code, Cursor, Codex, GitHub Copilot, Windsurf, OpenCode, and ~70 more agents from one command.

The installer needs Node/npx. The validate-banner skill itself runs on Python — so on a machine without Node you skip npx and install by plain copy instead (option B below).

Install this skill

A · With npx skills

npx skills add viewst/validate-banner-skill

Auto-detects your installed agents and symlinks the skill into each. Add --list to preview, -g for a user-global install, -a claude-code to target one agent.

B · Plain copy (no Node)

git clone https://github.com/viewst/validate-banner-skill.git
cp -R validate-banner-skill/skills/validate-banner \
   ~/.claude/skills/

Works anywhere python3 exists. Or run it directly: python3 …/validate-banner/validate.py banner.zip.

C · As a Claude Code plugin

/plugin marketplace add viewst/validate-banner-skill
/plugin install validate-banner@viewst

Uses the repo's .claude-plugin/marketplace.json + plugin.json.

Command & flags

npx skills add <source> [options]

The source can be a GitHub shorthand, a full URL, a git URL, a deep link to one skill, or a local path:

# all of these are valid sources
owner/repo
https://github.com/owner/repo
https://github.com/owner/repo/tree/main/skills/web-design
git@github.com:owner/repo.git
./my-local-skills
FlagWhat it does
-l, --listList the skills a source provides without installing.
-s, --skill <names…>Install only the named skills (use '*' for all).
-a, --agent <agents…>Target specific agents, e.g. claude-code, codex, cursor.
-g, --globalInstall to the user directory (~/) instead of the current project.
--copyCopy files instead of symlinking (when symlinks aren't supported).
-y, --yesSkip confirmation prompts.
--allInstall every skill to every detected agent, no prompts.

How discovery works

After fetching the repo, the CLI walks it looking for skills — a directory is a skill if it contains a SKILL.md with name and description frontmatter. It searches these locations (about two levels deep):

  1. Repo root — only if there's a SKILL.md there (a single-skill repo).
  2. skills/ and its curated subfolders (skills/.curated/, skills/.experimental/, skills/.system/).
  3. Manifests — .claude-plugin/marketplace.json or plugin.json, which can declare skills at explicit paths.
  4. Agent dirs — e.g. .claude/skills/, .agents/skills/.
Why we don't put SKILL.md at the repo root: a root-level SKILL.md would make the entire repository the skill payload — your README, LICENSE, and tests would all be symlinked into .claude/skills/. Nesting the skill under skills/validate-banner/ installs just that folder.

Minimum a skill needs

--- (frontmatter, required) ---
name: validate-banner
description: Validate an HTML5 banner against ad-network requirements…
--- (body: instructions for the agent) ---

How this repo is structured

Laid out so the skills/ walk finds exactly one skill and installs only its folder:

validate-banner-skill/
├── README.md, LICENSE, NOTICE  # repo-owned, never installed
├── .claude-plugin/
│   ├── marketplace.json  # enables /plugin marketplace add
│   └── plugin.json
├── docs/installing-with-npx-skills.html  # this page
└── skills/
    └── validate-banner/  # ← the installed unit
       ├── SKILL.md  # name + description frontmatter
       ├── validate.py  # Python runner (entry)
       ├── bannerlib/  # the engine (stdlib)
       ├── rules.json  # generated ruleset
       └── validate.mjs  # Node fallback runner
Because validate.py resolves rules.json and bannerlib/ relative to its own file, it keeps working through the symlink the installer creates — no matter the current working directory.
